# 2026-10-28 工作日志

## 修复: 超级壁纸 Windows 控制台乱码 + 壁纸层级覆盖图标

### 1) 控制台中文乱码
- 根因: `electron/wallpaper/main.js` 顶部用 `execSync('chcp 65001')` 想切编码，但 chcp 只在子进程生效，父进程(Electron)控制台代码页未变 → 中文 UTF-8 被当 GBK 显示乱码。
- 修复: 改用 koffi 调 `SetConsoleOutputCP(65001)`（Windows 下）；同时把 `package.json` 的 `electron:dev` 改为 `chcp 65001 >nul && electron .`（脚本级切控制台编码，覆盖 pnpm 管道转发场景）。

### 2) 壁纸盖住图标（attach WorkerW 失败，退化为覆盖层）
- 根因在 `electron/wallpaper/modules/wallpaper-engine.js`:
  - a) `GetLastError` 误绑在 `user32.dll`（实际在 `kernel32.dll`）→ init() 抛错中断，后续 SendMessageTimeoutA/EnumWindows 全没绑上 → attach 永远返回 false。
  - b) koffi 2.16.3 的 `lib.func(...)` **只返回函数，不会挂到 `lib.X` 属性**，原代码 `user32.FindWindowA(...)` 全是 undefined（被 a 挡住没暴露）。
  - c) `EnumWindows` 回调类型需用 `koffi.pointer(koffi.proto(...))` 包裹，原代码直接传 proto 会报 "Type X cannot be used as a parameter"。
  - d) `SetParent` 返回 64 位 HWND，原代码用 `int` 接收会被截断。
- 修复: 捕获每个 `func()` 返回值再调用；GetLastError 改从 kernel32 取；EnumWindows 参数用 `koffi.pointer(proto)`；SetParent 返回类型改 `void *`；HWND 用 BigInt 传递（koffi 接受 `void *`/`uint64` 接 BigInt）。
- 验证: 隔离环境 init 绑定无异常，EnumWindows 枚举 199 窗口并正确识别 SHELLDLL_DefView 图标容器（无界面环境无真实 WorkerW 属预期，真机由 0x052C 消息生成壁纸层）。

### 结论/待用户验证
- 用户重跑 `pnpm electron:dev`，日志应出现 `[WPE] *** SetParent OK! 壁纸已置于桌面图标之下`，而非 "退化为覆盖层模式"。

### 3) 二次修复: findWorkerW 找不到壁纸层
- 现象: 绑定 OK，但 `only icon container found, no wallpaper layer` → 仍退回覆盖层。
- 根因: 原代码用 `FindWindowEx(After=图标容器)` 在图标容器“之后”找壁纸层 WorkerW；但 0x052C 后 Explorer 把图标挪到新 WorkerW，**真正空的壁纸层 WorkerW 在 z 序里位于图标容器“之前”**，往后找永远为空。
- 修复(初版): `findWorkerW` 改为枚举【所有】顶层 `WorkerW`，取“不含 SHELLDLL_DefView”的那个；attach 加 0x052C 重试。

### 4) 三次修复: SetParent FAILED, GetLastError 87（参数非法）
- 现象: `findWorkerW` 已找到壁纸层，但 `SetParent(electronHwnd, workerW)` 返回 0，`GetLastError=87`(ERROR_INVALID_PARAMETER)，仍退回覆盖层；且 Win+D 也盖不住图标（overlay 模式顶在最上）。
- 根因（最终定位，两层）:
  - a) **koffi `void *` 返回类型返回 External 指针对象**（日志 `[External: 60d80081e790]`），而 Electron HWND 是 BigInt(`984828n`)。把 External 对象传回 `void *` 参数的 `SetParent` 时，koffi 传的是指针对象本身而非句柄值 → 参数非法 → 87。
  - b) `findWorkerW` 枚举【所有顶层】WorkerW 有歧义：本机实测有 14 个顶层 WorkerW 且**全都不含 SHELLDLL_DefView**（图标在 Progman 默认结构里，不在 WorkerW），导致 `workers.find(w => w !== null)` 取了第一个任意 WorkerW，大概率不是真正的壁纸层。
- 修复（定版）:
  - HWND 全部改 `uint64` 声明并以 BigInt/number 传递（**绝不用 void***）；实测 `SetParent(无效子窗口)` 返回 0 + `GetLastError=1400`（句柄无效），证明 uint64 编解码正确，之前的 87 确系 External 指针所致。
  - `findWorkerW` 改为优先取 **Progman 的直接子 WorkerW 中不含 SHELLDLL_DefView 的那个**（即 0x052C 生成的空壁纸层）；本机实测 Progman 恰好 1 个直接子 WorkerW(句柄 329734) 且为空，正是目标。兜底再枚举顶层。
  - `attach` 里 `SetParent` 成功后补 `SetWindowPos(electroHwnd, 0, 0,0, w,h, SWP_NOACTIVATE|SWP_FRAMECHANGED)` 把壁纸铺满 (0,0) 屏幕区域。
- **端到端真实验证（关键）**: 用系统 `Static` 类创建了一个真实测试窗口，`SetParent(test, 329734)` 返回 `65548`（上一个父窗口，非0）且 `GetLastError=0` → 挂载成功；`DestroyWindow` 干净销毁。证明 uint64 + Progman 空 WorkerW 目标 + SetParent 在本机完全可用。
- 结论: 乱码(1)与层级(2/3/4)三类问题均已修复，根因全在 `wallpaper-engine.js` 的 koffi 用法。

### 5) 小修: 壁纸底部 48px 黑边
- 现象: 用户日志 `SetWindowPos OK, size: 1920x1032`（高度比 1080 少 48px ≈ 任务栏高度）。
- 根因: `attach` 里 `SetWindowPos` 用了 `win.getBounds()` 的高度，Electron 把隐藏窗口高度按“工作区”收掉(减任务栏) → 壁纸底部露 48px 黑边。
- 修复: `init` 新增 `GetSystemMetrics` 绑定；`SetWindowPos` 改用 `GetSystemMetrics(0/1)` 取真实全屏分辨率(1920x1080)铺满，不再依赖 `getBounds()`。
- 验证: `GetSystemMetrics(0/1)` 返回 1920/1080，模块加载正常。
- 备注: 多显示器下此写法仅覆盖主屏，副屏铺满属后续“多显示器支持”任务（逐屏 attach + 各屏 rect）。

### 6) 纠正: 鼠标穿透不需要
- 用户实测桌面图标可点击、右键正常 → “鼠标穿透”并非必需，划掉 roadmap ①。
- 原因: 壁纸窗口是 WorkerW(桌面 shell 之下那层)的子窗口，点击自然落到上层 SHELLDLL_DefView(图标层)，壁纸碰不到鼠标。鼠标穿透只在旧的 alwaysOnTop overlay 模式(壁纸顶在最上)才需要，该模式已废弃。
